# TASK · 短视频脚本、证据与分镜

配套使用 `00_system.md`。TikTok/Feed 任务同时使用 `references/tiktok-short-video-playbook.md`。

## STEP 0 · 输入与证据门槛

先列出输入完整性。然后建立：

```markdown
## 卖点—证据映射
| 主张 | 可观察证据 | 演示动作 | 素材来源 | 能否兑现 | 风险/处理 |
```

`core_selling_point` 没有可观察证据时停止写成片台词，输出 `[PROOF_MISSING]` 与最小补拍清单。可以继续给拍摄方案，但不得把计划中的证据写成已经发生的结果。

## STEP 1 · 三种钩子机制

输出 3 个机制不同的候选，例如结果先给、痛点现场、演示挑战。每个候选包含：

| 字段 | 要求 |
|---|---|
| 首帧 | 0–0.5 秒具体动作，产品或结果已可见 |
| 母语钩子 | 0.5–1.5 秒可说完，不用自我介绍 |
| 证据预告 | 3 秒内告诉观众将如何证明 |
| 来源 | 评论、产品事实、真实顾虑或用户输入 |
| 可兑现性 | 无素材/参数支撑则失败 |
| 制作可行性 | 符合 `production_mode` 和现有素材 |

选择一个主钩子，并说明它匹配哪类当地用户顾虑。其他两个保留为测试变体。

## STEP 2 · 15 秒主版本

TikTok 默认先写：

| 时间 | 目标 | 内容 |
|---|---|---|
| 0–0.5s | 视觉中断 | 产品/结果/动作已出现 |
| 0.5–1.5s | 母语钩子 | 单一痛点或结果 |
| 1.5–3s | 证据预告 | 明确接下来如何证明 |
| 3–10s | 核心演示 | 问题 → 操作 → 可观察结果 |
| 10–13s | 异议处理 | 一个必要参数或顾虑 |
| 13–15s | CTA | 与平台能力和页面一致 |

用户要求 20/30 秒时，从主版本扩写证据、场景或异议处理，不加入第二条主线。

## STEP 3 · 分镜

每镜输出：

```markdown
| 镜号 | 时间 | 画面动作 | 本镜证据 | 素材来源 | 运镜/构图 | 母语字幕 | 安全区 | 声音 |
```

硬要求：

- 每镜只有一个动作，具体到可以拍摄或生成。
- 15 秒建议 6–9 镜；用节奏服务证明，不为快而快。
- 每 3–5 秒必须出现新的证据或状态变化。
- 真实实拍标 `[实拍]`，AI 镜头标 `[AI]`；AI 动画不得冒充测量或实测结果。
- 画面中的产品颜色、结构、配件和物理状态必须连续一致。
- 字幕最多两行，移动端可读，不遮产品或平台 UI。

## STEP 4 · 本地化检查

输出：

```markdown
| 项目 | 采用内容 | 依据/风险 |
| 市场语言与变体 | | |
| 当地产品称呼 | | |
| 场景与顾虑 | | |
| 单位/币种/电压 | | |
| CTA | | |
| 未使用的生硬俚语 | | |
```

没有当地语料支持时使用自然中性表达，不制造“本地感”。

## STEP 5 · 测试计划

首轮只替换钩子，保持演示、CTA、时长与剪辑节奏一致。列出 A/B/C 唯一差异、主假设、观察指标和失败后回改位置。不要凭空设定通用样本量。

## OUTPUT ORDER

1. 输入完整性与缺口
2. 卖点—证据映射
3. 三个钩子候选与选择
4. 15 秒主脚本（及用户要求的扩展版）
5. 逐镜分镜
6. 本地化检查
7. 时长校验输入稿
8. A/B 测试计划
9. 合规扫描
